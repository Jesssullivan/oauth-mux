# ADR-001 — Ordinary native application continuity

Status: ratified direction, 2026-10-02; experimental and unshipped.

**Existing user decision.** Install once, authorize sources once and run ordinary application commands. No Omux wrapper, routine handoff prompt, process restart or replacement session home is required by the product. Native transcript, tools, approvals and history remain authoritative. Existing processes are attachable only through a verified native integration.

**Implementation choice, reasserted 2026-10-05.** Omux owns the per-application authentication integration contract and implementation. No vendor-provided Omux hook is a dependency. Reversible native integration setup and supervised adapters connect applications to the resident daemon. An adequate existing extension mechanism may be used; otherwise Omux develops the native boundary. Delivery is qualified per application as plugin, configuration, upstream contribution or explicitly maintained application modification. Upstream acceptance is required only for the upstream delivery option. Codex is the first proof; Claude and Git follow. The [upstream Codex candidate](../../integrations/codex-upstream/README.md) is an experimental integration artifact; candidate evaluation is permitted, while unmodified Codex support and live acceptance remain unproved.

**Product sequence and installation ownership.** Install and activate → connect Chromium sources → verify identities and usable authority → maintain renewal → integrate ordinary applications → prove same-process handoff. Native UI onboarding uses shared CLI setup operations. Home Manager owns fleet packages, service definitions and exact-ID native-host registration; Omux owns runtime custody and user-authorized enrollment. Setup reports declarative changes instead of overwriting managed files. Development uses separate extension/service identities and custody.

**Acceptance / unresolved proof.** Exact application version and commit must demonstrate ordinary launch, native resume, existing-session attachment where supported, unchanged process and native state through provider-originated handoff. Candidate compilation and synthetic tests cannot satisfy this gate. Unmodified application controls alone do not establish the required integration; unsupported attachment must say why. Adapter delivery qualification and live conformance remain unresolved. Historical candidates and release evidence retain their original claim boundaries.
