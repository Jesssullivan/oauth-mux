# Retained public SDK dependency: proposed typed boundary

Status: source-only proposal; unadopted and all actual gates unrun. This record
does not establish build fit, installed support, ordinary resume or handoff.

Authority: the user's integrated implementation sprint and root design rulings
on October 14 authorize a new independent SDK-byte dependency and two-cohort
lease. The native account-lifecycle reset remains the product authority. The
existing transported SDK route, ContentDependencyLease, original SDK readers,
SOURCE600 and resource limits are unchanged.

## Produced bytes and current authority

`//tools:codex_native_retained_sdk_tree_materialized` produces one declared
TreeArtifact containing complete SDK/JDK bytes and the extraction receipt.
Its sibling inventory, program receipt, recipe and creator context are small
declared files. The ordinary action receives its actual executable runfiles
explicitly; it does not assume a TestRunner environment. Original extraction
uses an exclusive owned staging directory and a same-filesystem held rename,
without a second SDK copy or changing the existing Output/Root mode policy.

The manifest retains canonical logical modes, SHA values, literal links, empty
directories and NAR commitments. Only the new retained-tree reader derives
the narrowly defined Bazel all-regular0555 physical expectation. The original
Root and _FreshNarFile types remain unchanged. Every SOURCE consumer owns a
fresh full namespace, byte, SHA, NAR, semantic and final FD/name proof under
its original SOURCE600 context. A cached byte, creator verdict, file label or
reported clock is never present SDK execution authority.

The recipe commits actual declared code, complete tool runfiles, known-role
proof/control bytes and all four original carrier leaf pins. The original
carrier repository's fifth selection.json is a declared proof, not a payload
or public tool. Each group is sorted by logical path before commitment.
`action_inputs_sha256` is a semantic input commitment; it is not a Bazel
protobuf Action key.

The creator's shipping guard inputs are explicit. A source-only trace of its
actual materialize/qualify roots, metadata/family imports and runtime parser
found 63 project module basenames and no portable packaging import. The broad
resident guard list carried direct pack/portable sources and a fresh-runtime
support filegroup that also carried portable.py. Those paths serve resident
installation archive verification and native runtime packaging; neither
operation runs in SDK creation/qualification. Only the new SDK target omits
that unused guard closure. Its actual native production source chain remains
declared, while model test helpers stay in model targets. The new real Bazel
analysis test inspects the configured materializer runfiles for all 63 modules
and absence of model/portable packaging files. That test is unrun, and the
ordinary action/reuse gate remains mandatory.

## Parent lease and independent child proof

The new SDKTreeDependencyLease shares one output base for one checkout,
toolchain, identity and fixed isolation policy. It accepts exactly:

- producer: `native-sdk-tree-producer-reserved`, singleton
  `//tools:codex_native_retained_sdk_tree_producer`;
- consumer: `native-retained-sdk-tree-source-reserved`, exact model/producer
  pair `//tools:codex_native_siwc_catalog_tree_source_test` and
  `//tools:codex_native_siwc_catalog_tree_source_producer`.

The parent alone owns the exclusive cache lock and namespace lifetime through
containment and terminal publication. Prior receipts require exact cohorts,
checkout/key/output-base joins, kernel/resident projection, cleanup readback,
immutable evidence index and copied log/XML bytes. Failed epochs can retain
dependency data only and cannot create an SDK origin. Cancellation or failed
terminal qualification leaves the namespace unusable for reuse: a missing or
refused canonical receipt cannot match the marker's qualified terminal digest.
No foreign profile enters
this lease and no old ContentDependencyLease behavior is changed.

The child does not claim the parent-live lock. Its opaque authenticated owner
is constructed from the actual declared tree, fixed layout, selector, recipe,
nine held producer-proof roles and current SOURCE HeldControls. Typed prior
lease-origin facts establish provenance only; the child owns its current full
physical SDK proof independently. This public-build-data distinction cannot
be reused for credential, runtime adapter or account custody.

The initial whole source review rejected terminal publication before lease
completion and owned closes. The successor keeps a fixed `receipt.pending.json`
unselectable, qualifies its exact bytes/evidence through the parent owner, and
attempts all qualification-input FD closes before the final graph and original
cutoff joins. The actual cache writer lock and coordinator execution lock remain
held through the canonical `receipt.json` rename. That rename is the commit
point; staged file and directory fsyncs occur before it. No post-rename directory
fsync or power-loss durability is claimed. A crash that loses the canonical name
therefore refuses reuse; it does not inherit readiness from the clean marker.

A precommit failure can publish only a refused receipt with no SDK origin or
dependency disposition. A rename exception is commit-unknown. Canonical receipt
bytes alone are historical artifact provenance and are never an admissible
successful creator. The parent opens that canonical receipt through its held
epoch writer FD, performs a fresh byte/SHA/full-nine/named proof, and successfully
closes the new reader. Complete held/named and graph joins plus the original
1170 cutoff observation then precede creation of the mandatory independent
`sdk-tree-qualified.json` confirmation. It binds the exact canonical SHA/extent,
full-nine creator identity, epoch/context and observed qualification time.

Late, unconfirmed and crash-before-confirmation outcomes cannot qualify a
creator. Both structural selection and actual parent/child admission require
the independently held confirmation. Its later small metadata delivery stays
within the original outer1200 and attests already observed qualification; it
makes no later syscall timestamp claim and never extends SDK or SOURCE work.
Epoch, cache and coordinator writer locks remain held through that delivery.
After qualified confirmation, writer-release or reply failures preserve the
proved historical fact but report failed acknowledgement, without fictitious
rollback. Neither record grants a current parent-lock claim or SDK execution
authority; current consumers still establish their complete fresh physical proof.

Optional evidence may be copied, missing or stale. A copy-refused row is a
qualification refusal; mandatory test log/XML must be copied exactly once.
Parent and child parsers use this same grammar, and malformed parent XML is a
fixed typed refusal with actual evidence-owner drainage. The late evidence
directory join preserves its primary refusal when its owned close also fails.

Before a successful producer terminal receipt, the parent preserves four
complete public metadata files exclusively under the immutable epoch:
`sdk-tree-created/{creator-context.json,inventory.json,receipt.json,recipe.json}`.
It records ordered actual path/SHA/extent rows after full read/copy, close,
named-fence and original-clock checks. Subsequent test.outputs replacement
does not replace this history. The selector pins those immutable copies and
the actual direct TreeArtifact's four metadata bytes must match them.

## Clocks, limits and selection

The producer's original envelope is 1200 seconds, with 1170 seconds for work
and 30 for cleanup. The consumer payload keeps its original 600 seconds;
the existing 840 worker/action maximum and 1200 outer envelope are unchanged.
The parent terminal evidence/capture phase stays within the original 1170
cutoff. No phase resets or widens these clocks. Existing aggregate worker
3.75 GiB / 480 tasks / 190% CPU and resident 256 MiB / 32 tasks / 10% CPU remain the bounds.

The checked-in `native-retained-sdk-tree-inputs.json` starts UNSELECTED/null.
Only a genuine successful independently qualified producer plus all joined
physical proofs can support a reviewed selection update. Missing or evicted
bytes never trigger a new SOURCE-owned SDK stage. An expired creator action
must refuse cold replay; a fresh separately bounded producer is required.
No disk/remote cache flag, FAILEDNS-PHASES scratch, fixture-populated selector
or ancestor SDK execution verdict provides an alternative authority.
