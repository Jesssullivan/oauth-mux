## Interfaces and implementation conditions

Public delivery channels are `release` and `development`; runtime instance
selection is `OMUX_INSTANCE=default|dev`. The explicit mapping must be validated
at each boundary. Native host names are `ai.xoxd.omux` and
`ai.xoxd.omux.dev`. Channel identity, extension ID, service, socket and custody
must agree before mutation. Labels and browser provenance do not establish
provider account identity.

`setup.readiness` presents separate installation, service, custody, source,
identity, usable-grant and native-capability findings. `setup.plan` describes
ownership-aware changes; it never represents a proposed change as completed.
The CLI and thin UIs consume this shared model. A provider-free `browser.health`
handshake reports protocol/channel capability without enrolling an account.

The additive `setup.applicationReadiness` query and stdin-only
`omux application-readiness -` accept an explicitly selected application and
optional concrete request demand. They join source, verified identity, request
grant custody/generation, renewal owner, capacity and adapter configuration
within one lineage and actor revision. The opaque context digest binds the
application, normalized demand, revision and installation. Reads decrypt no
credential and create no lease or mutation. Stale or unavailable custody yields
unknown; acquisition and ordinary native launch remain unverified. The query
does not correlate an enrollment operation or expose a selected source ID.
Preserve the independent source/operation view and the original seven-phase
setup schema. Current source is under compiled/actor/CLI validation; declarations
alone establish no usable native integration or achieved service objective.

Explicit `omux setup verify` and thin-client Verify setup use the optional
identified `setup.refresh` mode with exactly `operation_id` and
`expected_revision`. Empty refresh remains a diagnostic; passive readiness
reads add no durable attempt. The existing mutation ledger owns the started
fence, prepaid completion space and immutable seven-phase terminal result.
Status queries recover the same operation; unknown, indeterminate or malformed
replies never authorize another verification. Shutdown before the terminal
commit preserves unresolved authority. `verification_completed` reports a
finished local check, with ready/action-required/unknown phase facts; it does
not establish installation, activation, enrollment or native handoff success.
`reliability.lifecycle.setup_verification` derives bounded summaries from those
existing records, without another ledger or schema migration. Process-local
timing excludes commit/reply latency and does not satisfy the complete
ID-RELIABILITY measurement gate. The dated 13:36 source slice was unrun during
the allocation hold. The user resumed execution after restoration at 16:03;
fresh declared test results and exclusions are recorded in the
[resume receipt](../tracker-updates/integrated-delivery-resume-2026-10-05.json).
No acceptance gate is promoted by the source addition. See the
[session receipt](../agent-notes/2026-10-05-sess-omux-integrated-delivery.md).

Browser consent and disconnect target the selected context. Explicit disconnect
ends source acquisition/admission authority and deletes that source's retained
secret material, preserving independently valid grants and native history.
Disappearance uses detachment semantics. Unknown mutation completion remains
pending until reconciled; retry cannot invent a new logical operation.

Production acquisition remains disabled until reviewed fields, fixed identity
verification, purpose, context, expiry and custody are demonstrated. Imports
retain external renewal ownership; adoption requires verified transfer and
retirement of the former writer. The extension cannot turn browser-bound
authority into a portable application grant.

The artifact manifest binds exact bytes, source provenance, channel, extension
identity, native host and compatibility. Nix consumes declared Bazel output;
there is no second application build graph or recursive Nix/Bazel bootstrap.
Managed paths use direct immutable references or the exact bounded Home Manager
generation-leaf topology, with descriptor custody and declarative reconciliation.
Manual receipt-owned installation remains distinct.
