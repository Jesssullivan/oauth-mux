# Native Codex authentication hook candidate

This is a reviewable upstream patch against official [`rust-v0.157.0`](https://github.com/openai/codex/tree/00c972ed5d6ff6499317fd41b7f23605b8e6850d), commit `00c972ed5d6ff6499317fd41b7f23605b8e6850d`. The annotated tag object is a different hash, recorded in `manifest.json`. No maintained Codex distribution is shipped today, and this candidate is not native continuity support. Omux owns its application adapter; upstream contribution and maintained modification are delivery options to qualify under the [current integrated plan](../../docs/plans/omux-integrated-delivery-sprint-2026-10-05.md).

The patch implements optional native `[omux_broker]` configuration, thread-local late registration/removal, and request-owned access authorization. Stock Codex lacks the required methods and remains observable. Existing threads require a reachable native local control endpoint; embedded instances without one cannot be attached.

## Native wire

The native app-server accepts `omux/broker/capabilities`, `omux/broker/register`, `omux/broker/unregister` and `omux/broker/thread/status`. Registration params are `threadId`, `bindingId`, `brokerSocket`, `capabilityPath` and `protocolVersion: 1`. The response includes `bindingId`, `protocolVersion`, `refreshOwnershipAcknowledged` and capability flags. The acknowledgment concerns access-only model requests: the hook never adopts or refreshes a native refresh lineage.

Unregister params are `threadId` and optional `releaseBinding`. Native callers default to `releaseBinding: true`; native removal schedules a bounded `adapter.releaseBinding` callback without delaying the control response. That callback carries the latest `expected_lease_handle`, so delayed cleanup cannot release a newer daemon binding. Omux-coordinated disconnects send **`releaseBinding: false`** because the daemon owns their release. This prevents a callback into the single-writer daemon while it awaits the native acknowledgment.

Ordinary future native launches read:

```toml
[omux_broker]
broker_socket = "/private/user/runtime/omux/adapter.sock"
capability_path = "/private/user/state/omux/integrations/codex.capability"
```

Both paths must belong to the current user, reside in private directories, and deny group/other access. The capability is exactly 64 hexadecimal bytes and is sent only on the private adapter channel. Socket peer credentials must match the current user. Each model request snapshots its binding and replay fence.

Detachment requires an idle loaded thread, a nonrunning agent and inspectable portable native history. Active or opaque histories are rejected without editing native state. Successful detachment retains a native reentry marker: ambient authentication and prewarming stay blocked until the actual next request input passes the opaque-context check. This second gate catches context added by a racing final response after the control-plane history check. It clears account transport affinity before restoring native requests; destroyed thread instances remove the marker during teardown.

Before each model request the hook calls `adapter.acquire` with application `codex`, the native thread binding, a unique request ID, exact model demand and audience `https://chatgpt.com`; it calls `adapter.materialize` for an access token, expiry, provider account routing and route generation. No refresh token enters Codex. `adapter.report` records rejection, acceptance, completion and abandonment. A guard takes ownership immediately after a structurally valid lease is decoded, before expiry validation, and records expired acquisitions, preparation failures, cancellation, stream errors and early EOF as terminal abandonment. A valid lease transfers synchronously to the caller's request guard. Unacknowledged cleanup retains the daemon's in-flight fences beyond credential expiry until an authorized terminal report resolves them; expiry never proves native work finished. Abandonment never authorizes replay.

## Request safety

Broker model requests use native HTTP/SSE and the fixed official Codex endpoint. Configured ambient authorization, account routing, cookies and turn affinity are excluded. Account-generation changes clear cached WebSockets, incremental references and turn routing. Native thread/turn metadata, full request input, history, tools and approvals remain under Codex authority.

An explicit HTTP 401, 403 or 429 rejection before stream creation may obtain exactly one alternate before native error presentation. The HTTP client has no automatic request retry. The outer Responses retry handler is fenced for broker requests, including accepted-stream errors, unexpected EOF and tool-drain errors. An ambiguous network outcome cannot trigger substitution or resampling.

Full HTTP input can contain account-bound encrypted reasoning, encrypted tool arguments, compaction content or uploaded-file IDs. Initial attachment or an account change fails closed when these cannot be reconstructed. Same-account credential generations may invalidate transport without discarding opaque history. This is an explicit restriction, not an assertion that those provider-owned objects are portable.

`omux/broker/thread/status` returns `threadId`, `bound` and nullable `lastObservedRoute`. It reads only a local cache; status and registration acknowledgments never call the broker, acquire credentials or poll a provider. Request execution refreshes metadata asynchronously through `adapter.metadata`. A typed allowlist retains only broker account/grant handles, user labels, lifecycle, expiry and route metadata, excluding tokens, provider account IDs and unknown fields. Each cached observation has `observed_at`. Refresh checks the response account and generation against both its captured lease and the locked current route; route changes clear the cache. Missing or old observations remain missing or old, rather than implying current account eligibility or quota.

The native `/status` view reads this cache for the selected thread before considering native account usage. Requests and completions carry the thread and a monotonic request generation; another thread's response or an older unbound observation cannot replace the selected route. The card displays only validated account labels, account type, provider, independent provider/custody expiries and observation age. Missing values remain unknown; observations older than fifteen minutes are labeled stale, and future timestamps report a clock mismatch. The view does not infer quota from expiry or fetch browser/provider data.

Ordinary native launch, resume, CLI login-status and native account UI recognize an explicit `brokerManaged` control mode. They skip unrelated canonical login, refresh, account filtering, account mutation and quota reporting. Broker configuration alone never claims a selected provider account or entitlement. Explicit native CLI login/logout remain available for independent native enrollment; an already running app-server enrollment retains its native authorization permit until completion or cancellation, so late adoption stays unavailable until it drains.

Successful late adoption puts the process-shared model manager into a monotonic descriptive mode. It returns bundled model descriptions, omits native account filtering, drops pending native discovery work and rejects later native cache publication. This catalog mode lasts until the process exits, including for unbound threads sharing that manager. A request already dispatched before adoption cannot be recalled. Global account/auth, account mutation and usage RPCs have no per-thread broker authority: they redact or reject canonical native access while any thread is bound or awaiting safe native reentry. Bound auxiliary provider operations without declared request custody fail closed.

Adoption also drains retained remote plugin work and the old MCP runtime before registration. The shared plugin manager then stays in a local-only mode that preserves installed local bundles and skills without native account cache or remote entitlement reuse. Unsupported Codex Apps, remote plugin mutations, uploads, realtime and memory operations cannot borrow a canonical native credential. Native ancillary permits remain owned by their actual worker lifetime; cancelled connector discovery retains its permit until the owned MCP runtime shuts down. A cancelled native Apps subscription has no server terminal acknowledgment, so its authorization fence remains until process exit and can prevent late attachment. Cancellation does not establish ownership transfer.

Live golden promotion must separately establish ordinary launch/resume admission, existing-thread attachment, concurrent account isolation, provider-originated rejection recovery, native history/tools/approvals preservation and opaque context portability. Thread-specific cached broker status is separate from Codex's process-global native account RPC. The artifact remains `native_support: false`; live continuity evidence is unavailable. Passing the source oracle or upstream tests does not change stock Codex support metadata.
